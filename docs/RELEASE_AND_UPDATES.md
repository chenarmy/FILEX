# FILEX release and update runbook

## Repository configuration

Create a dedicated key pair for FILEX. Do not reuse the GITBX key, even if the same maintainer publishes both products.

```powershell
pnpm tauri signer generate -w "$env:USERPROFILE\.tauri\filex.key"
```

Back up the private key offline. Configure these GitHub repository settings:

| Kind | Name | Value |
| --- | --- | --- |
| Actions Secret | `TAURI_SIGNING_PRIVATE_KEY` | Complete private-key file content or a runner path |
| Actions Secret | `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | Password chosen during generation; omit only when the key has no password |
| Actions Variable | `FILEX_UPDATER_PUBLIC_KEY` | Complete text content of `filex.key.pub`; do not Base64-encode it again |
| Actions Secret | `CNB` | CNB token allowed to push tags and create/update releases in `chenarmy/FILEX` |

To produce the public-key variable value without reading the private key:

```powershell
(Get-Content "$env:USERPROFILE\.tauri\filex.key.pub" -Raw).Trim()
```

The `.pub` file generated by Tauri already contains the Base64 text that the updater expects.

The same key pair must never be replaced after a signed version has been distributed to users. A new public key requires a separate migration path.

## Prepare a release

1. Set the version in all manifests:

   ```powershell
   pnpm version:set 0.1.1
   pnpm install --lockfile-only
   cargo check --workspace
   ```

2. Add a non-empty `## [0.1.1] - YYYY-MM-DD` section to `CHANGELOG.md`.
3. Run the local gates:

   ```powershell
   pnpm version:check
   pnpm lint
   pnpm typecheck
   pnpm test
   pnpm build
   cargo fmt --all -- --check
   cargo test --workspace
   cargo clippy --workspace --all-targets -- -D warnings
   ```

4. Commit the synchronized version and changelog.
5. Create and push the matching tag:

   ```powershell
   git tag v0.1.1
   git push origin v0.1.1
   ```

## Automated release gates

The release workflow:

1. checks out the tag and verifies all version sources;
2. signs a temporary fixture to prove the configured private key, public key and signed-version behavior match;
3. reads the version's release notes from `CHANGELOG.md`;
4. builds a visible Windows/macOS/Linux draft;
5. downloads and cryptographically verifies the updater metadata and signatures;
6. publishes GitHub only after the exact asset set passes;
7. mirrors the same assets to CNB and rewrites `latest.json` to CNB URLs;
8. verifies the mirrored CNB release contains the expected assets.

Release builds embed these stable feeds in order:

```text
https://github.com/chenarmy/FILEX/releases/latest/download/latest.json
https://cnb.cool/chenarmy/FILEX/-/releases/latest/download/latest.json
```

The Tauri updater advances after a connection, HTTP or manifest-parse failure. Once a manifest parses successfully, a missing or invalid artifact signature remains a security failure and never falls back to an unsigned update.

## Verify after publication

1. Confirm the GitHub release is public, marked latest, contains `latest.json`, and includes every required installer, updater bundle and `.sig` file.
2. Download `latest.json` from both feeds and compare version, signature and platform keys.
3. Confirm CNB asset URLs replace the GitHub release-download URLs while retaining the same signature bytes.
4. Install the current signed build, publish the next patch version, then use Settings → Updates to check, confirm, download and install it.
5. Record the observed version before and after restart, installer channel, manifest source, signature result and any platform-specific failure in `docs/VERIFICATION.md`.

Do not mark automatic updates complete until one signed release has been installed over an older signed release on each supported platform.

## Recovery

- If a build fails, the release remains a draft.
- If verification fails, do not manually publish the draft; fix the workflow or version and run again from the tag.
- If CNB mirroring fails after GitHub publication, rerun the failed job or dispatch the manual CNB mirror workflow for that tag.
- Never re-sign a different artifact under an already published version. Publish a higher patch version instead.
